# 오답기록 — CPA Study (MVP 1.0)

**Noteful 또는 Flexcil + Apple 단축어 + 설치형 웹앱**을 위한 개인 오답 기록 시스템입니다.

원본 문제 이미지, 오답 원인, 교정 기준, 재풀이 결과, 백업을 한곳에서 관리합니다. 계정, 서버 데이터베이스, 유료 API 또는 AI 모델은 필요하지 않습니다.

## 1. 제공 파일

- `index.html`, `styles.css`, `app.js`: 화면과 주요 기능
- `store.js`: 원본 이미지와 노트의 IndexedDB 저장, SHA-256 확인, 복습 간격
- `backup.js`: 원본 파일을 포함한 ZIP 백업과 무결성 검사, 복원
- `sw.js`: 오프라인 캐시
- `manifest.webmanifest`, `icon-*`, `icon.svg`: 홈 화면 앱 설치용

이 파일을 모두 동일한 웹사이트 경로에 올립니다. **파일 앱에서 HTML을 직접 여는 방식은 정식 사용 환경이 아닙니다**. 보안 컨텍스트(HTTPS)와 IndexedDB를 제공하는 주소로 열어야 합니다.

## 2. 배포: GitHub Pages (무료로 시작하는 예)

1. https://github.com 에 로그인한 뒤 `cpa-error-log`라는 새 **Public repository**를 생성합니다. (무료 GitHub Pages를 사용하는 예이며 코드만 공개됩니다. 공부 자료는 GitHub 저장소에 업로드하지 않습니다.)
2. 이 ZIP의 `cpa-error-log-mvp` 폴더 **안의 파일들**을 저장소의 루트에 업로드합니다. 원본 문제 이미지나 백업 ZIP은 업로드하지 않습니다.
3. 저장소의 **Settings → Pages → Build and deployment → Deploy from a branch → main / (root) → Save**를 선택합니다.
4. 배포가 완료되면 `https://계정이름.github.io/cpa-error-log/`를 iPad Safari에서 엽니다. 저장소 이름을 다르게 설정했다면 해당 경로로 바꿉니다.
5. Safari의 공유 버튼 → **홈 화면에 추가** → **웹앱으로 열기**(표시되는 경우) → 추가. 이후부터 **홈 화면 아이콘으로만** 등록, 복습, 백업합니다.
6. 첫 번째 테스트용 오답을 등록하고, 즉시 **백업 및 복원 → 전체 백업 ZIP 만들기**로 파일이 iPad 파일 앱에 저장되는지 확인합니다.

**중요:** GitHub Pages는 HTTPS 웹앱 파일을 제공할 뿐이며 오답 원본을 서버로 전송하지 않습니다. 모든 오답은 실행 중인 브라우저/설치된 앱의 IndexedDB에 저장됩니다. Safari 브라우저와 홈 화면 웹앱 저장소는 **서로 별개**일 수 있습니다. Safari에서 저장한 오답을 홈 화면 앱에서 볼 수 없으면 데이터가 삭제된 것이 아니라 저장 컨테이너가 다른 것입니다. 필요한 경우 같은 위치에서 백업·복원하세요.

## 3. Apple 단축어 구성 (iPad)

iPad에서 `단축어` 앱을 열고 다음과 같이 직접 만듭니다.

1. `+`를 눌러 새 단축어를 만들고 이름을 **오답 캡처 복사**로 지정합니다.
2. 단축어 세부사항에서 **공유 시트에서 보기(Show in Share Sheet)**를 켜고 입력 유형을 **이미지**로 제한합니다.
3. 동작에 **클립보드에 복사(Copy to Clipboard)**를 추가합니다. 복사할 대상을 변수 **단축어 입력(Shortcut Input)**으로 지정합니다.
4. 저장하고, 먼저 사진 앱의 PNG 스크린샷을 공유 → **오답 캡처 복사**를 실행해 테스트합니다.
5. 홈 화면에 설치된 **오답기록** 앱으로 전환 → **오답 등록** → **클립보드 이미지 가져오기** → 오답 이유 및 교정 기준 입력 → 저장.

권장 실제 사용 흐름: **Noteful에서 필요한 문제 영역을 스크린샷으로 캡처 → 공유 → 오답 캡처 복사 → 홈 화면 오답기록으로 전환 → 클립보드 이미지 가져오기 → 오답 이유 기록 → 저장**.

- 단축어가 Noteful의 공유 메뉴에 나타나지 않을 때는, 문제를 **스크린샷**으로 캡처한 후 iPad 스크린샷 미리보기 또는 사진 앱의 공유 메뉴에서 실행합니다.
- 클립보드 이미지 읽기는 **웹앱의 사용자가 직접 버튼을 눌러** 요청합니다. iPadOS가 붙여넣기 허가를 요청할 수 있습니다.
- 단축어에서 **Open URLs(웹사이트 열기)**를 자동으로 넣지 않는 이유: Safari가 실행되어 홈 화면 웹앱과 **다른 저장소**에 카드가 등록될 수 있기 때문입니다. 자동 열기는 검증 전에는 사용하지 않습니다.
- 클립보드 가져오기에 실패한다면 스크린샷을 **사진/파일 앱에 저장**하고, 오답기록의 **파일 선택**에서 가져옵니다.
- PDF를 공유하는 경우 위 단축어의 이미지 전송 경로가 아니라 오답기록의 **파일 선택**으로 PDF를 직접 가져옵니다.

## 4. 기능

| 기능 | MVP 구현 |
|---|---|
| 문제 원본 | PNG, JPG, WEBP, PDF 업로드 / 클립보드 이미지 / 원본 파일 그대로 저장 |
| 노트 | 틀린 이유·교정 기준 **둘 다 필수**, 과목, 단원, 출처, 오류 유형 |
| 관리 | 제목 및 오답 내용 검색, 과목 필터, 복습 필요 필터 |
| 복습 | 정답을 가린 뒤 재풀이, **풀이 완료 후에만** 오답 원인 표시, 맞음/틀림 기록 |
| 일정 | 등록 후 1일, 정답이면 3 → 7 → 14 → 30 → 60 → 120일, 틀리면 1일로 초기화 |
| 무결성 | 원본 저장 SHA-256, 수동 해시 재검사, 백업 및 복원 시 SHA-256·ZIP CRC 검사 |
| 백업 | 원본 이미지와 모든 텍스트, 복습 기록을 **하나의 ZIP**으로 다운로드 |
| 복원 | 기존 자료 유지 + 새로운 ID만 추가 또는 명시적 확인 후 전체 교체. 동일 ID 내용 충돌 시 병합 거부 |
| 오프라인 | 앱 파일을 최초 온라인 접속 시 캐시, 이후 오프라인으로 실행 가능(기기 설정 영향) |

## 5. 정확성과 안전

- 이미지의 수식, 숫자, 글자를 인식해 다시 타이핑하지 않습니다. 업로드한 바이트를 그대로 IndexedDB에 저장합니다. 클립보드에서 가져온 경우 **클립보드가 제공한 PNG 등 파일 바이트**가 보존되며, 앱이 원래 Noteful 문서 바이트와 일치한다고 주장하지 않습니다.
- 사용자가 파일을 자르거나 스크린샷 편집을 했다면 **편집 후 이미지**가 기준 원본입니다.
- 메모를 수정해도 등록된 문제 원본은 교체되지 않습니다. 잘못 첨부한 경우 별도 카드로 다시 등록하세요.
- 모든 자료가 기기 안에 있어 기본적으로 자동 동기화되지 않으며, 백업 ZIP은 **사용자 스스로** iCloud Drive·외장 디스크 등 여러 곳에 보관해야 합니다.
- 앱이 오프라인이라는 사실이 데이터 보존을 보장하지 않습니다. iPad 저장소 압박, 앱 제거, 브라우저 기록 삭제, 초기화 등에 대비해야 합니다.
- **GitHub Pages 프로젝트를 삭제하거나 URL을 변경하지 않는 것**이 좋습니다. 웹앱 저장소가 웹사이트 출처(origin)에 묶여 있기 때문입니다.
- 앱 실행에 제3자 코드를 불러오지 않으며, 네트워크 요청은 앱 자체 정적 파일을 받아오는 데만 사용합니다.

## 6. 현재 제한 및 후속 개발

- Noteful/Flexcil의 **내부 버튼이나 API를 직접 수정할 수 없습니다**. 단축어를 통한 복사 + 웹앱 붙여넣기가 현재 현실적인 통로입니다.
- iPad Safari의 PWA는 **시스템 공유 대상(Web Share Target)**을 지원하지 않으므로 앱으로 직접 공유하는 자동화는 아직 없습니다.
- 서버 동기화, 푸시 알림, OCR 자동 분할, AI 분류, 필기 인식, 원본 PDF의 페이지 직접 링크, 멀티 페이지 PDF 특정 영역 발췌, 여러 이미지 합치기는 MVP 범위 밖입니다.
- 단일 원본 첨부 최대 35MB. 백업 **복원 ZIP 최대 250MB**, 파일 **최대 5000개**. 큰 데이터셋에는 스트리밍 ZIP 및 분할 백업이 필요합니다.
- 이 버전은 개인정보를 전송하지 않는 로컬 MVP이나, 기기를 함께 사용하는 사람이나 기기의 파일 백업에 접근 가능한 사람에게 학습 자료가 노출될 수 있습니다. 중요한 개인 정보가 적힌 문제는 미리 가리세요.

## 7. 개발자 로컬 실행

프로젝트 폴더에서 `python3 -m http.server 8080` 실행 후 `http://localhost:8080`으로 열 수 있습니다. iPad에서 사용하려면 HTTPS 주소(GitHub Pages 등)를 사용해야 합니다.

## 8. 백업 복원 시험

1. 더미 이미지 1개 등록 → 원본 해시 검사 통과 확인.
2. **백업 및 복원** → ZIP 생성 → 다운로드된 파일이 있는지 확인.
3. **백업 ZIP 복원(기존 자료 유지)** → 기존 카드 ID가 중복으로 건너뛰어지는지 확인.
4. 새 브라우저/별도 앱에 같은 ZIP을 복원하여 내용 및 이미지가 일치하는지 확인.
5. 매주 또는 중요한 학습 세션마다 다시 ZIP 백업하세요.
